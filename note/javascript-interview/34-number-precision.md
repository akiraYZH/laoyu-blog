JavaScript 中一个经典问题是：

```js
0.1 + 0.2 === 0.3; // false
```

这不是 JavaScript 随机算错，而是有限位二进制浮点数无法精确表示许多十进制小数。

## 1. 为什么有限存储会产生近似值

十进制中的 `1 ÷ 3` 是无限循环小数：

```text
0.3333333333...
```

数学上可以表示这个无限结果，但计算机内存有限，只能保存某个近似值。二进制浮点数也会遇到同样问题：`0.1`、`0.2` 转成二进制后都是无限循环小数，只能在有限位数处舍入。

## 2. JavaScript 的 Number

JavaScript 的 `Number` 使用 IEEE 754 双精度浮点格式。它大致由三部分组成：

```text
符号位 + 指数部分 + 有效数字部分
```

总长度为 64 位，但不是 64 位都用来保存整数本身。有限的有效数字位数决定了它只能保存二进制近似值。

## 3. 0.1 与 0.2 的二进制结果

资料展示的近似二进制相加过程是：

```text
0.1 ≈ 0.000110011001100110011...
0.2 ≈ 0.001100110011001100110...
```

相加并舍入后得到的值转回十进制是：

```js
0.1 + 0.2; // 0.30000000000000004
```

所以：

```js
0.1 + 0.2 === 0.3; // false
```

两边保存的实际浮点值并不完全相同。

## 4. 查看实际精度

`toPrecision()` 可以用指定有效数字位数显示数值：

```js
(0.1).toPrecision(16);
// "0.1000000000000000"
```

显示更多位时就能看到近似误差：

```js
(0.1).toPrecision(21);
// "0.100000000000000005551"
```

这并不是 `toPrecision()` 制造了误差，而是它把内存中的近似值显示得更完整。

## 5. 安全整数范围

JavaScript 能精确表示的最大安全整数是：

```js
Number.MAX_SAFE_INTEGER; // 9007199254740991
```

它与 `2^53 - 1` 相等。超过这个范围后，不是每个整数都能精确表示：

```js
9007199254740992 === 9007199254740993; // true
```

随着数值区间增大，可表示整数之间的间隔也会增大：

- `2^53` 到 `2^54` 附近，只能精确表示间隔为 2 的整数；
- `2^54` 到 `2^55` 附近，间隔进一步变为 4；
- 数值越大，可表示点越稀疏。

判断整数是否安全：

```js
Number.isSafeInteger(9007199254740991); // true
Number.isSafeInteger(9007199254740992); // false
```

## 6. 浮点数的最大范围

指数部分让 `Number` 能表示非常大的值，但也有限制：

```js
Math.pow(2, 1023);
// 8.98846567431158e+307

Math.pow(2, 1024);
// Infinity
```

达到可表示范围之外后会变成 `Infinity`。

## 7. 显示结果：toPrecision 后再转数字

如果只是希望把 `1.4000000000000001` 显示或归一为 `1.4`，资料使用：

```js
parseFloat((1.4000000000000001).toPrecision(12)) === 1.4;
// true
```

封装：

```js
function strip(number, precision = 12) {
  return +parseFloat(number.toPrecision(precision));
}

console.log(strip(1.4000000000000001)); // 1.4
```

这适合处理展示误差，但不是所有金融或高精度计算的通用解决方案。

## 8. 运算前放大为整数

对于小数加法，可以统计小数位数，统一放大成整数后运算，再缩小：

```js
function add(num1, num2) {
  const num1Digits = (num1.toString().split(".")[1] || "").length;
  const num2Digits = (num2.toString().split(".")[1] || "").length;
  const baseNum = Math.pow(10, Math.max(num1Digits, num2Digits));

  return (num1 * baseNum + num2 * baseNum) / baseNum;
}

console.log(add(0.1, 0.2)); // 0.3
```

思路是：

```text
0.1 × 10 = 1
0.2 × 10 = 2
(1 + 2) ÷ 10 = 0.3
```

资料提醒：加、减、乘、除需要分别处理，不能简单对所有运算套同一个 `toPrecision()`。

> 说明：即使“先放大为整数”，中间乘法本身仍可能受到浮点误差和安全整数范围影响。金额系统更可靠的方式是从输入字符串解析最小货币单位，或使用十进制定点/高精度库。

## 9. BigInt 与高精度库

超出安全整数范围、且只做整数运算时，可以使用 `BigInt`：

```js
const value = 9007199254740993n;

console.log(value + 1n); // 9007199254740994n
```

`BigInt` 不能直接表示小数，也不能与普通 `Number` 直接混合算术。

需要高精度十进制小数时，资料建议使用第三方库，例如：

- `bignumber.js`；
- `Math.js`；
- `BigDecimal.js`。

这些库通常把数字按字符串或内部十进制结构处理，避免直接依赖二进制浮点近似。

## 10. 比较浮点结果

如果业务允许误差，可以比较差值是否小于容差：

```js
function nearlyEqual(a, b, epsilon = Number.EPSILON) {
  return Math.abs(a - b) < epsilon;
}

console.log(nearlyEqual(0.1 + 0.2, 0.3)); // true
```

对于量级很大的数，容差通常还要结合数值大小设计，不能对所有业务固定使用同一个绝对误差。

## 11. 总结

1. `0.1` 和 `0.2` 在二进制浮点中只能保存近似值，所以相加不严格等于 `0.3`。
2. `Number` 使用 IEEE 754 双精度格式，有效精度和指数范围都有限。
3. 最大安全整数是 `2^53 - 1`，更大的整数可能发生间隔跳跃。
4. `toPrecision()` 加 `parseFloat()` 可以整理展示结果，但不是高精度计算的万能方案。
5. 常见小数运算可以先转整数再计算，但仍要检查安全整数和中间误差。
6. 超大整数使用 `BigInt`，高精度十进制计算使用专门库或最小单位整数方案。
